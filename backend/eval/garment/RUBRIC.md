# 옷 분석 AI 평가 기준 (Rubric)

평가 대상은 옷 사진 분석(`apps/wardrobe/analysis.py`의 `analyze_image`)이다.
옷 사진 한 장을 OpenRouter 비전 모델에 보내 옷의 대분류(상의·하의·아우터)와 종류(티셔츠, 청바지, 코트 등)를 포함한 속성 JSON을 받는다.

이 파일과 `cases.json`, 이미지는 **평가를 처음 실행하기 전에 커밋**하며, 결과를 보고 케이스나 기준을 바꾸지 않는다.

## 평가셋 (`cases.json`, `images/`)

- 고정 케이스 **45개**: 상의 15, 하의 15, 아우터 15
- 이미지는 팀이 AI로 생성한 옷 사진(펼쳐 놓은 옷, 흰 배경)이다. Heuristic Evaluation 때 더미 옷장으로 쓴 사진과 같고, K-Fashion·AI Hub 데이터는 포함하지 않는다.
- **정답**은 각 사진을 생성할 때 지정한 옷 종류다(파일 이름 `대분류_종류_번호.jpg`).
  - 대분류: `top`, `bottom`, `outerwear`
  - 종류: 앱의 종류 목록(`apps/wardrobe/schema.py`의 `SUBCATEGORIES`)과 같은 이름이다. 셔츠는 여성 셔츠가 블라우스로도 보일 수 있어 `shirt`와 `blouse`를 모두 정답으로 인정한다. 나머지는 하나만 정답이다.

## 케이스 채점 (자동, 사람 판단 없음)

| 항목 | 맞음 조건 |
|---|---|
| 대분류 | 출력 `category`가 정답과 같음 |
| 종류 | 출력 `subcategory`가 정답 목록에 있음 |
| 형식 | 응답이 앱의 응답 형식 검증을 통과함 (`analyze_image`가 `AnalysisError`의 형식 오류 없이 결과를 돌려줌) |

- 형식 검증에 실패한 응답은 **형식 오류**로 세고, 대분류·종류도 틀린 것으로 센다.
- 모델이 사진을 거부한 경우(`IMAGE_*`, 예: 옷이 여러 벌로 보임)는 형식 오류가 아니라 **틀림**으로 센다.
- 네트워크·제공자 오류(`AI_TIMEOUT`, `AI_UNAVAILABLE`, `AI_PROVIDER_ERROR`, `AI_RATE_LIMITED`)는 **인프라 오류**다. 같은 케이스를 최대 2번 다시 시도하고, 그래도 실패하면 채점에서 빼고 따로 기록한다.
- 키·잔액·모델 설정 오류(`AI_AUTH_FAILED`, `AI_CREDITS_REQUIRED`, `AI_MODEL_UNAVAILABLE`, `AI_REQUEST_INVALID`)가 나면 모델의 판단이 아니므로 평가를 멈추고, 설정을 고친 뒤 처음부터 다시 실행한다.

## 통과 기준

| 지표 | 기준 |
|---|---|
| 대분류 정확도 | **≥ 95 %** |
| 종류 정확도 | **≥ 85 %** |
| 형식 오류 | **0건** |
| 해결되지 않은 인프라 오류 | 0건 (1건 이상이면 판정은 INCOMPLETE) |

세 지표를 모두 만족하면 **PASS**, 하나라도 못 미치면 **FAIL**이다.

## 기록

결과는 `results/<실행 시각>.json`에 저장한다: 모델 이름, 실행 시각, 케이스별 출력·정답·맞음 여부·응답 시간, 지표, 판정.
색상·핏·스타일처럼 사진만으로 정답을 정하기 어려운 속성은 이 평가에서 채점하지 않는다.
