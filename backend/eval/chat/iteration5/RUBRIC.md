# 채팅 AI 평가 · Iteration 5 추가 세트

평가 대상과 채점 방법은 기본 세트와 같다([../RUBRIC.md](../RUBRIC.md)): `chat_intent.parse`의 요청 해석을 `expect`에 적은 필드만 자동 채점한다.
기본 세트(34개)를 만든 뒤에 생긴 요청 유형을 따로 모은 세트이며, 이 파일과 `cases.json`은 **처음 실행하기 전에 커밋**하고 결과를 보고 바꾸지 않는다.

## 평가셋 (`cases.json`, 24개, 기본 세트와 같은 가상 옷장 14벌)

| 분류 | 개수 | 확인하는 것 |
|---|---|---|
| `trip` 날짜·장소·상황 | 6 | 날짜와 장소는 규칙(`trip.py`)이 읽으므로, 모델은 요청을 거부하지 않고 상황이 뜻하는 방향(하객룩 → 단정하게, 바닷가 → 시원하게 등)을 준다 |
| `add_outer` 아우터 추가 | 3 | 아우터가 없는 코디에 아우터를 더하는 요청(PR #82) |
| `follow_up` 되묻기 뒤의 답 | 3 | 직전 대화에서 어시스턴트가 되물은 뒤 짧게 답한 요청을 이어서 해석 |
| `informal` 구어·줄임말 | 4 | "ㄱㄱ", "넘", "꽉끼는듯" 같은 말투 |
| `multi` 여러 조건 | 4 | 슬롯별 다른 방향, 피할 색 + 방향, 아우터 빼기 + 변경, 유지 + 지정 |
| `unsupported`·`undo` | 4 | 가방·없는 옷·날씨 질문은 되묻기, "아까 걸로"는 되돌리기 |

## 통과 기준 (기본 세트와 같음)

| 지표 | 기준 |
|---|---|
| 케이스 통과율 | **≥ 80 %** |
| 치명적 오류 (반대로 해석) | **0건** |
| 형식 오류 | **0건** |

인프라 오류는 기본 세트와 같이 재시도하고, 남으면 INCOMPLETE로 기록한다.

## 실행

```bash
python scripts/eval_chat.py --cases eval/chat/iteration5/cases.json
```

결과는 `eval/chat/iteration5/results/<실행 시각>.json`에 저장된다.
