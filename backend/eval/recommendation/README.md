# 추천 엔진 평가 실행

고정 케이스와 통과 기준은 [RUBRIC.md](RUBRIC.md)를 따른다. 케이스(`cases.json`)와 기준은 첫 실행 전에 커밋했고([9cbd9a8](https://github.com/snuhcs-course/swpp-2026-project-team-14/commit/9cbd9a8)), 결과를 보고 바꾸지 않는다.

## 실행

`backend/`에서 (Django·네트워크·API 키 없음, 서버와 같은 모델 파일 사용):

```bash
python eval/recommendation/run.py               # A와 B (B는 로컬 kfashion_dataset/ 필요)
python eval/recommendation/run.py --part rules  # A만
```

결과는 `results/<실행 시각>.json`에 저장된다. 같은 커밋에서 다시 실행하면 같은 결과가 나온다(케이스마다 시드 고정).
케이스를 다시 만들 때만 `make_cases.py`를 쓴다. 이미 커밋한 `cases.json`을 덮어쓰지 않는다.

## 결과 (2026-11-12, `results/20261112-172339.json`)

| 평가 | 결과 | 기준 | 판정 |
|---|---|---|---|
| A 규칙 준수 (옷장 40개, 코디 360개) | 342/360 = 95.0 % | ≥ 95 % | PASS |
| B 명백히 나쁜 코디 피하기 (쌍 100개) | 95/100 = 95.0 % | ≥ 90 % | PASS |

- A의 위반 18개 중 17개는 같은 원인이다. 9 °C 미만에서 엔진은 보온이 2.0보다 낮은 아우터(재킷, 카디건 등)를 빼는데, 옷장에 그런 아우터만 있으면 "맞는 아우터가 없어" 상의·하의만 고른다. 기준표로는 재킷도 맞는 아우터라 알린 예외가 아니라 위반으로 셌다. 나머지 1개는 상의를 잠근 요청에서 코디가 2개만 나온 경우다.
- 내 옷만 쓰기, 작은 옷 제외, 잠금 유지, 반복 없음은 위반 0건이다. 알린 예외(맞는 옷이 정말 없어서 가장 가까운 옷을 쓰고 알린 경우)는 36개다.
- B는 겨울 반바지·겨울 민소매·한여름 패딩 쌍을 모두(75/75) 맞혔다. 스타일 충돌(클래식 코디 + 조거팬츠·래깅스)은 20/25다. 틀린 5쌍은 실제 코디의 궁합 점수부터 낮았고(C 4–33), 바꾼 하의가 그 기온에 더 맞아 계절 점수도 올랐다.
