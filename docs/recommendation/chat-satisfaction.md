# 채팅 만족도 평가 기준

HE 결과 집계 전에 이 기준과 구현을 커밋한다. 실제 평가 결과를 확인한 뒤 기준을 변경하지 않는다.

| 항목 | 기준 |
| --- | --- |
| 평가 대상 | 명시한 HE 참여 계정이 채팅 결과 카드에서 남긴 평가 |
| 집계 단위 | 사용자·옷 조합별 최신 평가 한 건 |
| 기간 | `--since` 이상, `--until` 미만. 시간대 포함 ISO 8601 필수. 종료 생략 시 실행 시각 |
| 참여 계정 | `--participants`에 HE 참여자 아이디를 지정한다. 팀·테스트 계정은 포함하지 않는다 |
| 제외 | 취소·미평가, 홈·코디북 평가, 기간 밖 평가, 지정하지 않은 계정 |
| 최소 표본 | 유효 평가 20건. 서로 다른 사용자·옷 조합을 센다. 참여자 수와 별도로 출력한다 |
| 만족도 | 좋아요 / (좋아요 + 별로예요) |
| PASS | 유효 평가 20건 이상이며 만족도 50% 이상 |
| FAIL | 유효 평가 20건 이상이며 만족도 50% 미만 |
| INCOMPLETE | 유효 평가가 20건 미만 |

기존 50% 기준을 유지하고 최소 20건 조건을 추가했다. 참여자 목록과 HE 시작 시각은 데이터 수집 전에 확정하고 같은 기준 커밋에 기록한다. 이 문서의 명령에 있는 아이디는 예시이며 실제 평가 계정으로 교체한다.

```powershell
cd D:\swppgit\swpp-2026-project-team-14\backend
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py chat_satisfaction --since "2026-11-03T00:00:00+09:00" --until "2026-11-04T00:00:00+09:00" --participants he_user01 he_user02
```

실제 HE 날짜에 맞춰 기간을 지정한다. 존재하지 않는 계정이나 잘못된 기간은 오류로 처리한다. 동일한 집계 기간과 참여 계정 목록을 결과와 함께 보관한다. 집계는 현재 남아 있는 최신 평가를 조회하며 종료 시점의 과거 상태를 재현하는 이벤트 이력 평가는 아니다.

## 저장과 취향 반영

- `FeedbackRecord(channel=chat)`는 사용자·옷 조합에 유일하며 평가 변경 시 갱신하고 취소 시 null로 남긴다. 저장 재시도는 평가 시각을 바꾸지 않는다.
- `FeedbackRecord(channel=outfit)`는 기존 홈·코디북 취향 학습 이벤트이며 채팅 만족도 집계에서 제외한다.
- `FeedbackTaste`는 처음 평가를 기록하기 전의 기기 취향을 계정별로 보관한다. 이후 취향은 기록된 옷 속성 스냅샷을 기존 감쇠·상한 알고리즘에 적용해 계산한다. 채팅 평가 취소는 해당 학습을 제외하며 다른 평가를 보존한다.
- 마이그레이션은 두 테이블을 추가한다. 기존 코디와 공용 평가를 보존하며, 입력 화면 출처가 없는 과거 평가는 새 채팅 평가 기록으로 자동 변환하지 않는다.

## 회귀 검증

```powershell
.\.venv\Scripts\python.exe manage.py test apps.outfits --settings=config.test_settings --noinput
```

검증 대상은 좋아요→코디북 저장→취소→재평가, 중복 코디의 단일 집계, 다른 평가를 유지하는 취향 재계산, 서버 평가 상태 조회·계정 분리, 기간·참여 계정 필터, 최소 표본과 50% 경계다. 단위 테스트의 합성 데이터 결과와 실제 HE 만족도 결과를 구분한다.
