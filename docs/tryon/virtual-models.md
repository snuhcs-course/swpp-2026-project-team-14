# 가상 모델로 입어보기

가상 피팅에서 왼쪽은 내 갤러리 사진, 오른쪽은 체형이 비슷한 AI 모델 사진을 선택한다. 두 방식 모두 동일한 Nano Banana 2.1의 2K 이미지 편집 API를 사용한다. 가상 모델 원본 사진은 미리 생성하여 APK에 포함하며 사용자 요청마다 다시 생성하지 않는다.

develop의 필수 로그인 구조를 따른다. 오늘의 코디·코디북의 피팅은 로그인한 계정의 옷만 사용하며, 요청·조회·결과 다운로드·삭제 API 모두 계정 인증이 필요하다. 생성 작업은 해당 계정과 작업 토큰을 함께 확인한다.

피팅에는 화면 표시용 썸네일 대신 서버에 등록된 사진을 전송한다. 착용 사진에서 잘라낸 옷(`worn_crop`)은 `model`, 일반 옷 사진과 AI 평면화 사진은 `flat-lay` 입력으로 처리한다.

## 모델 사진

- 남녀 각각 키 4구간과 체격 3구간을 조합한 12장, 총 24장이다.
- 정면 전신, 몸에서 조금 떨어진 팔, 단순한 회색 티셔츠·반바지·흰 운동화, 회색 배경으로 통일했다.
- 체격 차이는 허리·복부·팔·다리 실루엣으로 표현하고 부정적인 체형 표현이나 과장된 묘사를 사용하지 않았다.
- 아래 키·몸무게는 사진 생성과 선택을 위한 대표 기준이다. 실제 인물을 측정한 수치나 사용자의 신체를 정밀 복원한 결과가 아니다.

| 성별 | 키(cm) | 슬림 기준(kg) | 보통 기준(kg) | 여유 있는 체격 기준(kg) |
| --- | ---: | ---: | ---: | ---: |
| 남성 | 160 | 50 | 59 | 69 |
| 남성 | 170 | 56 | 66 | 78 |
| 남성 | 180 | 63 | 75 | 87 |
| 남성 | 190 | 70 | 83 | 97 |
| 여성 | 150 | 43 | 50 | 59 |
| 여성 | 160 | 49 | 56 | 67 |
| 여성 | 170 | 55 | 64 | 75 |
| 여성 | 180 | 62 | 71 | 84 |

사진 경로: `frontend/app/src/main/assets/tryon/models/v1/{성별}_{키}_{체격}.webp`. 24장 합계 약 0.6MB이며 각 사진은 576×864다. 원본은 내장 imagegen 도구로 생성했고, APK 패키징 과정에서 WebP로 변환했다. [개별 생성 프롬프트와 기준값](virtual-models-prompts.json)에 재생성 정보를 기록했다.

## 선택과 보관

1. 저장된 체형 정보의 성별과 가장 가까운 키 구간을 고른다.
2. 해당 구간에서 키 대비 몸무게 비율이 가장 가까운 모델을 고른다.
3. 체형 정보가 없거나 성별·몸무게가 비어 있으면 사진 없이 성별·키·몸무게만 입력한다. 이 입력은 이번 피팅 선택에만 사용한다.
4. 선택한 가상 모델 사진을 사용자 사진 대신 기존 피팅 API에 보낸다. 상의·하의·아우터 입력과 추론 방식은 동일하다.
5. 결과는 사용자·코디·사진 출처와 모델 사진 수정 버전별로 기기에 보관한다. 갤러리 결과와 가상 모델별 결과는 서로 덮어쓰지 않는다. 같은 방식으로 다시 열면 결과를 재사용한다.
6. 결과의 왼쪽 저장은 갤러리 저장, 오른쪽 확인은 팝업 닫기다.

선택한 갤러리 원본은 수정하지 않는다. 백그라운드 전송을 위해 축소한 JPEG 사본을 앱의 백업 제외 개인 저장소에 임시 보관하고, 서버 접수 후 삭제한다. 접수 전 작업 생성 실패나 중단이 확인된 경우에도 임시 사본을 정리한다. 피팅 사진은 OpenRouter와 Google로 전송된다. StyleMate 서버의 입력은 처리 후 삭제하며 외부 제공사에는 해당 보관 정책이 적용된다. 완료된 결과만 앱의 개인 저장소에 남는다. 미리 생성한 공용 모델 사진은 APK 자산으로 유지한다.

생성은 백그라운드에서 진행한다. 피팅 완료 알림의 기본값은 ON이며, 사용자가 저장한 OFF 설정은 유지한다. 피팅 화면 우측 상단 벨의 ON/OFF는 사용자별로 저장하여 오늘의 코디와 모든 코디북에서 공유하고, 앱 재실행 후에도 유지한다. 별도 알림 확인 팝업은 없다. Android 13 이상에서는 알림이 ON인 상태로 피팅 화면을 처음 열거나 벨을 켤 때 필요한 시스템 알림 권한을 요청하며, 거부하면 OFF로 저장한다. 완료 알림을 누르거나 해당 코디의 가상 피팅을 다시 열면 저장된 결과를 확인할 수 있다.

## 코드 정리

- FASHN GPU 엔진·별도 FastAPI 워커·GPU 프록시·SAM2 마스크 합성과 가중치 다운로드·GPU 전용 Docker/의존성을 제거했다.
- Django가 한 번의 OpenRouter 호출로 상의·하의·아우터를 함께 생성한다. 자동 재시도나 FASHN 대체 경로는 없다.
- 기존 피팅 DB를 이관하거나 복구하지 않는다. 생성 작업은 메모리에만 보관하고, 새 테스트 DB에서 검증한다.
- APK 모델 사진, 현재 계정별 결과 저장, 백그라운드 작업과 알림은 기능에 필요한 구성으로 유지한다.
